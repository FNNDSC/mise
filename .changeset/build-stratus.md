A Trusted Domain can now be built on OCI from the session, and torn down. The build runs through Resource Manager and Red Hat's Assisted Installer, as harbor-oci proved it. `domain new --compartment` names where it goes. Preflight reads the credential, the compartment, the attribution tag, the room in each availability domain, the load balancers free, the zone's delegation and the SSH key, and refuses a spec with workers, since only the compact cluster is proven. The discovery image is copied into a private bucket and linked for a week; the link is kept as a secret. A new stack's variables come from the spec, the apply's outputs give the load balancers and the platform manifest, and the three A records are written in the zone. The installer takes a service account's token without a scope, fetches the pull secret each time, waits for every host to be known, and starts the install when the cluster is ready; the kubeconfig and the administrator's password are kept on the host. `domain teardown <name>` reads the cluster's own volumes, shows what goes, asks for the domain's name, then destroys the stack's resources and removes the records, the image and its link, those volumes and the installer's records; it refuses an adopted domain or one read from a checkout. New launch flags: --redhat-account and --ssh-key.
