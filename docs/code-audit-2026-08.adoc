== Status and purpose

This is a point-in-time audit of the mise monorepo (cumin, salsa, chili, brasa, chell, calypso) at main `2fd60e4`, taken as a deliberate pause after the 2026-08 feature run (brasa extraction aftermath, identity-keyed daemons, output routing, the PACS recovery work). The trigger was concrete: two production incidents in one week, the folder-context cache poisoning and the silent PACS retrieve loss, shared a single root pattern, errors absorbed at a boundary and converted into success-shaped values. That pattern is auditable, so this document audits it, along with the complexity, duplication, coverage, cast, and cache-contract debt visible from the same vantage point.

Method: scoping, rubrics, and final verdicts by the lead session; two mechanical sweeps (error absorption, complexity) executed by subordinate model runs against those rubrics; coverage and cast inventories generated by istanbul and grep; the cache-contract inventory written directly from subsystem reading. Sweep verdicts were adjudicated rather than accepted: the highest-impact findings were re-verified against source, and several are confirmed by this week's incident forensics rather than by static reading alone. Counts below are candidates where marked, confirmed where stated.

This document relates to existing records as follows: the error-absorption findings extend the failure analysis in link:pacs-pull-recovery.adoc[pacs-pull-recovery.adoc]; the cache-contract inventory extends the freshness discipline recorded in link:calypso.adoc[calypso.adoc]; the cast inventory revives the dormant chrisapi adapter-contract effort.

== Finding 1: silent error absorption (the incident class)

The sweep classified 93 absorption sites: 32 bug-likely, 10 unclear, 51 deliberate-and-correct. The deliberate majority is healthy, best-effort cleanup, cosmetic fallbacks, completion UX, and documented multi-format probing all legitimately swallow. The bug-likely third is not.

=== Confirmed high-severity

These were re-verified against source, and two are the exact defect class that caused this week's incidents, still present at sibling sites.

`packages/salsa/src/vfs/providers/pacs.ts:386,395`: a study or series UID not found during listing returns `Ok([])`, rendering "not found" as an empty directory. This is the identical pattern fixed in `native.ts` this week, one provider over.

`packages/salsa/src/vfs/providers/native.ts:196-198`: `path_checkIsDir` swallows its own listing failure into `false`. This function is now the probe that decides missing-versus-empty for the native provider, so a transient failure inside it converts a healthy folder into "No such file or directory". The fix for the last incident stands on an unguarded absorption.

`packages/chell/src/remote/remoteEngine.ts:208`: a malformed or schema-invalid daemon message is dropped without a log, leaving the correlated pending request hanging forever. A protocol drift between daemon and client versions would present as a silent hang.

`packages/salsa/src/vfs/dispatcher.ts:167-172`: both path-resolver calls in `cp` carry fully empty catches; a resolution failure silently proceeds with the unresolved path.

`packages/salsa/src/dag/feedJoins.ts:68-72`: a transient instance-fetch failure permanently loses topological join edges, since a guard prevents retry after the empty write.

`packages/salsa/src/vfs/providers/proc.ts:610-621`: `rm` on a feed ignores every per-job `job_cancel` Result and reports success regardless.

=== Failure-reads-as-empty family

A recurring sub-pattern converts fetch failure into an empty collection, indistinguishable from "genuinely none": `store/index.ts:15,25` (store list and search), `commands/compute/list.ts:23` and `commands/plugins/add.ts:89` in chili (compute resources, with `add` defaulting to `['host']`), `jobs/jobOps.ts:203,213` (status batch and per-instance fetch), `path/pathCommand.ts:510` (recursive walk). Each site should either surface the error or return a Result the caller must inspect.

=== Diagnosability family

Sites that do fail visibly but destroy the cause: `utils/docker.ts:41` (stderr discarded, logging commented out), `filesystem/fileGroupHandler.ts:69` and `plugins/pluginGroupHandler.ts:60` (real error replaced by generic "no ChRIS context"), `path/pathCommand.ts:777` (fixed "folder does not exist" regardless of cause), `chefs/chefs.ts:130`, `controllers/baseController.ts:52`, `controllers/feedController.ts:59`, `context/contextCommand.ts:207`, chell `config/settings.ts:100,118` (settings silently not persisted), cumin `connect/chrisConnection.ts:371` (all token-read errors read as "no token"), calypso `daemon/berth.ts:181,207` and `daemon/discovery.ts:59` (corrupt berth files read as "no daemon").

The 10 unclear sites (full list in the sweep record) mostly need a one-line decision each: either document the absorption as deliberate or add the missing surface.

== Finding 2: complexity and duplication

The sweep ranked 41 hotspots. The headline is duplication rather than raw length: the codebase repeatedly re-solves problems it has already solved.

Duplication clusters, worst first: the attempt-count-plus-backoff retry loop is implemented independently four times (`pull.ts task_fire`, `pacsUtils.ts series_cubePathGet`, `query.ts pacsQuery_createAndWait`, `startupWarmup.ts startupPrefetch_retry`); the series-to-CUBE-folder lookup exists in three packages (`chrisPACS.ts seriesStorage_resolve`, `pacsUtils.ts series_cubePathGet`, `pacs.ts series_getFolderPath`), the third copy added by this very week's work; the `_qid:` extraction regex appears three times across two packages; an identical `while(true)` pagination loop appears five times inside `proc.ts` alone; the transfer-loop-with-progress shape appears four times across chili; the correlation-id RPC broker shape appears five times across calypso's server and chell's remote engine; and salsa's `pacs.ts` contains a poll-based PACS retrieve watcher that solves the same domain problem as `pull.ts`'s LONK watcher.

Two findings are free wins: `chili/src/path/pathCommand.ts:157-496` is a dead, unreferenced second implementation of the directory scan, and `download.ts` duplicates its own stream-download loop internally.

Size and responsibility hotspots: `chili/commands/fs/download.ts files_downloadWithProgress` (250 lines), `salsa/pipelines/invocation.ts pipelineInvocation_prepare` (192 lines, depth 6), `chell/core/startupWarmup.ts startupWarmup_run` (183 lines), `brasa/builtins/fs/pull.ts builtin_pull` (173 lines, six responsibilities, plus the 136-line `tasks_pullWatch`), and `calypso/daemon/server.ts CalypsoDaemon` (five concern kinds in one class). Top files by hotspot count: `pathCommand.ts` (5), `pull.ts` (4), then `download.ts`, `proc.ts`, `pacs.ts` (3 each).

== Finding 4: cast inventory

65 `as unknown as` casts: salsa 23, brasa 19, chili 16, chell 4, cumin 3, calypso 0. Concentrations: `salsa/vfs/providers/proc.ts` (8), `salsa/jobs/jobOps.ts` (7), `brasa/builtins/fs/pull.ts` (5). Most launder the chrisapi client into ad hoc structural types (`ChRISPACSClient`, `ChRISTokenClient`), which is precisely the hole the locked cumin adapter-contract seam was designed to close. That effort predates the brasa extraction and stalled; the inventory says it is still worth finishing, starting with the PACS and jobs client surfaces.

== Finding 5: cache contracts

Four caches, four different freshness stories, only two of them sound.

`listCache` (cumin): TTL per path pattern, explicit invalidation including the new subtree form, dirty tracking, optimistic stale serving. Sound, with two known gaps: `mv` and `cp` do not tree-invalidate their source and destination subtrees, and `pacs query` does not invalidate the `/net/pacs/queries` listing.

`ProcCache` (cumin): terminal status immutable and checkpointed, active status refreshed live, freshness states explicit. Sound and documented; the model the others should follow.

Object-context factory (cumin): process-lifetime cache, folder contexts now exempt after the incident. Residual exposure: plugin and feed contexts are cached forever, so a deleted-and-recreated plugin or feed id would serve a dead binding. Rare, but the same shape as the folder bug and worth a one-line eviction hook.

`_queryCache` (salsa PACS provider): unbounded, process-lifetime, no invalidation. A decoded query result cached from a partially complete query stays wrong forever, and the map grows monotonically in a daemon. This is the folder-context bug's shape waiting for its incident; it needs a TTL or an explicit settled-only rule like ProcCache's.

== Decisions (stress-tested 2026-08-21)

The plan below was interrogated axis by axis before execution; four decisions bind it. First, error surfacing is hard: every failure-reads-as-empty site converts to the codebase's pervasive `Result<T>` pattern (`Err()` plus an errorStack push that drains into the envelope), errors reach stderr, and exit codes go non-zero. No known consumer depends on empty-on-failure, and exit 0 on a failed fetch is the exact lie that caused this month's incidents. Second, the pause is the correctness pause: P1, P2, and P4 execute now; P3's mechanical dedup and P5's ratchet are future work applied as files are touched. Third, the two large convergences (the five-fold correlation-id RPC broker and the dual PACS watchers) are pulled forward into a scheduled design pass immediately after the correctness pause rather than trigger-deferred: the broker abstraction is consolidation of a five-times-proven shape, the watcher split is a user-visible inconsistency (`cp` and `pull` of the same PACS path behave differently), and a unified broker gives envelope Phase-2 one clean place to thread typed messages. The watcher convergence requires live-CUBE verification, not just unit tests, and the broker unification must stay wire-compatible behind the existing message schema. Fourth, releases batch: one publish after the correctness pause carrying the queued cache-fix and PACS-recovery changesets together with the P1/P2/P4 changesets, the error-surfacing behavior change stated prominently in its own changeset. Execution order: P1, P2, P4, convergence design pass, then envelope Phase-2.

== Remediation plan

Ordered by risk retired per unit effort. Each phase is independently shippable; nothing here blocks feature work.

*P1, incident-class correctness (small, do first).* Fix the confirmed high-severity absorptions: pacs VFS not-found-as-empty, `path_checkIsDir` self-absorption, remoteEngine silent message drop, dispatcher `cp` empty catches, feedJoins permanent edge loss, proc `rm` ignored cancels. Then the failure-reads-as-empty family (store, compute, jobs, walk). Roughly a dozen sites, each a few lines plus a test.

*P2, diagnosability (small-medium).* The remaining bug-likely sites: preserve the real error where a generic message replaces it, log where settings and berth files silently fail, and adjudicate the 10 unclear sites into deliberate-documented or fixed.

*P3, dedup (medium, highest structural payoff).* Extract shared helpers in dependency order: one bounded-retry-with-backoff utility (kills four copies and standardizes the incident fix), one series-storage resolver in cumin (kills three copies including this week's), one `_qid:` parser, one pagination helper for `proc.ts` (kills five), one transfer-progress loop for chili (kills four). Delete the dead `pathCommand.ts` scan outright. Defer the RPC-broker unification and the dual-PACS-watcher convergence to their own design pass; both are real but not mechanical.

*P4, cache contracts (small).* Bound `_queryCache` (settled-only caching plus eviction), add `mv`/`cp` subtree invalidation, invalidate the queries listing on `pacs query`, add an eviction hook to the object-context factory. Record each cache's contract in one place, extending the calypso.adoc freshness section.

*P5, coverage ratchet plus decomposition (ongoing).* Lift the worst dual-listed files first (`pacs.ts`, `invocation.ts`, `cliSurface.ts`, `client.ts`, `chrisFeed.ts`, `screen.ts`), raising per-package thresholds as each lands so the ratchet holds. Decompose the three worst functions (`files_downloadWithProgress`, `pipelineInvocation_prepare`, `builtin_pull`) as they are next touched for features rather than as a standalone rewrite, using the P3 helpers as the extraction seams. Resume the chrisapi adapter contract to burn down the 65 casts, PACS and jobs surfaces first.
