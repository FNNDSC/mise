= What the kernel covers of a CUBE feed
:toc: macro

toc::[]

== Abstract

A CUBE feed is more than its graph of jobs: it has a title, a note, comments, tags, permissions, a public flag and a folder of files. This page lists each part of the feed resource the CUBE API offers, the kernel verb or path that reaches it, and what the surfaces do with it. It exists because #831 began from a gap ("two CUBE feed API features that are not covered — tags and notes"), and a gap nobody lists is a gap nobody sees. The rule it holds to is the house one: missing functionality is materialized in the kernel first (cumin, salsa, brasa), and a surface only ever runs the kernel's verbs (no bypassing mise).

Status as of 2026-10-03. A row marked *not covered* is a known gap, not an oversight.

== The feed resource

[cols="2,3,3,2",options="header"]
|===
| CUBE resource | Kernel verb or path | Surfaces | Status

| The feed list (`/api/v1/` feeds collection)
| `/proc/jobs` (a feed per `feed_N`), `proc feeds` (the roster model `feed.list`), `feeds list`
| chell `ls /proc/jobs`; ARGUS RUNS roster, UNIVERSE
| Covered

| A feed's jobs (plugin instances)
| `/proc/jobs/feed_N/<plugin>_<id>/…` (status, params, log, data link), `feed tree`, `feed diagram`
| chell; ARGUS DAG pane, census
| Covered

| A feed's title (`name`)
| `/proc/jobs/feed_N/title` (read)
| chell `cat`; ARGUS bars and roster
| Read only. Renaming a feed (`PUT name`) is *not covered*.

| A feed's note
| `/proc/jobs/feed_N/note` (`cat` reads, `touch --withContents=` writes, `edit` edits); `feed note N [--title\|--content]`; `feed note edit N` (= `edit` on the file)
| chell `$EDITOR`; ARGUS EDIT pane, EDIT NOTE / ADD NOTE on an entered feed's graph
| Covered (#831). A note is read only when its feed is entered: the feed list says nothing about notes (CUBE gap, ChRIS_ultron_backEnd#737).

| A feed's comments
| `feed comments N`, `feed comment add\|edit\|delete`
| chell
| Covered in the kernel; no ARGUS surface yet.

| Tags (the user's) and taggings (tag ↔ feed)
| `/proc/tags` (`ls`, `mkdir`, `rmdir`, `mv`); `getfattr feed_N`, `setfattr -n tag -v <t> feed_N`, `setfattr -x tag [-v <t>] feed_N`; `#tags` in `ls -l`
| chell; ARGUS tag marks on RUNS rows and an entered feed's graph, TAG question, `tag:` filter
| Covered (#831: kernel #849, ARGUS #850). A tag's colour (set in CUBE) is kept, not painted.

| User permissions (sharing to an identity)
| `setfacl -m u:<user>:r feed_N`, `getfacl feed_N`
| chell; ARGUS SHARE verb and the row's SHARED WITH readout
| Grant and read covered. Revoking a grant is *not covered* (refused by name).

| Group permissions
| none
| none
| *Not covered*: the API offers `addGroupPermission` and `getGroupPermissions`; `setfacl` refuses group entries.

| Public flag (`makePublic` / `makeUnpublic`)
| `feeds share <id>` (make public)
| chell
| Make public covered; making a feed private again is *not covered*, and the verb is a sentence rather than a shell metaphor (a `chmod`-like verb would fit the house rule).

| The feed's folder of files
| `/home/<user>/feeds/feed_N/…`, every file verb (`ls`, `cat`, `cp`, `mv`, `rm`, `download`, `edit`)
| chell; ARGUS files pane
| Covered

| Deleting a feed
| `feed rm <feed>`, `rm /proc/jobs/feed_N`
| chell; ARGUS DELETE verb (the kernel asks)
| Covered

| Creating a feed
| `feed create <path>`, `pull --new-feed`, `pipeline run`, PROCESS
| chell; ARGUS PROCESS, cohort CREATE FEED
| Covered
|===

== Reading this page

Where a row says *covered in the kernel* and names no ARGUS surface, the console in ARGUS still reaches it: every kernel verb runs there. A surface adds a gesture only when the gesture is the better way in; the verb stays the source of truth. When a gap is closed, its row changes in the same PR as the code (#831 changed the note and tag rows).
