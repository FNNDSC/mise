== What this is

The intent API is the pairing of `@fnndsc/cumin` (connection lifecycle, the typed wire contract, resource primitives, the `Result<T>` error discipline) and `@fnndsc/salsa` (file operations, feeds, jobs, pipelines, PACS retrieval). A program built on it states intentions: connect as this user, make this directory, stage this series, run this plugin, and receives typed results rather than raw collection documents.

== Why this is

CUBE's REST surface is correct but request-shaped: creating a feed, attaching an analysis and reading its output takes a choreography of collection lookups that every script would otherwise reimplement, and reimplement slightly wrongly. The intent layer performs that choreography once, in one audited place, and its error discipline is uniform: fallible operations return `Result<T>`, failure carries its cause on an error stack, and nothing is silently absorbed.

== How this relates to existing clients

link:https://fnndsc.github.io/fnndsc/chrisdoc/index.html[@fnndsc/chrisapi] remains the canonical low-level client, and mise consumes it behind a single adapter seam rather than competing with it; the type-laundering casts that once spread through consuming code are confined there and held by a ratchet. If your program needs a raw collection the intent layer does not model, the escape hatch is deliberate and typed: see the wire contract in the link:api/modules/_fnndsc_cumin.html[cumin reference].

== The examples are tests

Every code block below is included, by tag, from an exemplar program in `packages/chell/exemplars/ts/`. The exemplars run in continuous integration against a live CUBE and leave it exactly as they found it (every created resource registers its own undo on a cleanup plan). What you read here executed, recently, for real. The harness helpers you will see, `check`, `step`, `section`, `CleanupPlan`, live beside the exemplars in `lib/harness.ts` and are plain assertion and cleanup conveniences, not part of the API.
