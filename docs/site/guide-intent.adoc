== What this is

The intent API is the pairing of `cumin` (connection lifecycle, the typed wire contract, resource primitives, the `Result<T>` error discipline) and `salsa` (file operations, feeds, jobs, pipelines, PACS retrieval); the packages install as `@fnndsc/cumin` and `@fnndsc/salsa`. A program built on them states intentions: connect as this user, make this directory, stage this series, run this plugin, and receives typed results rather than raw collection documents.

== Why this is

CUBE's REST surface is correct but request-shaped: creating a feed, attaching an analysis and reading its output takes a choreography of collection lookups that every script would otherwise reimplement, and reimplement slightly wrongly. The intent layer performs that choreography once, in one audited place, and its error discipline is uniform: fallible operations return `Result<T>`, failure carries its cause on an error stack, and nothing is silently absorbed.

== How this relates to existing clients

link:https://fnndsc.github.io/fnndsc/chrisdoc/index.html[@fnndsc/chrisapi] remains the canonical low-level client, and `cumin` consumes it behind a single adapter seam rather than competing with it; the type-laundering casts that once spread through consuming code are confined there and held by a ratchet. If your program needs a raw collection the intent layer does not model, the escape hatch is deliberate and typed: see the wire contract in the link:api/modules/_fnndsc_cumin.html[`cumin` reference].

== The examples are programs, and the programs are tests

Every example below is a complete, standalone program, included on this page in full: imports, entry point, exit codes. They live in `packages/chell/exemplars/ts/standalone/` and continuous integration runs them against a live CUBE, so an example that stops working turns the build red rather than the page stale. Copy one whole, point `CUBE_URL`, `CUBE_USER` and `CUBE_PASSWORD` at your instance, and it runs.

== A filesystem round trip

Files live in the ChRIS filesystem, addressed by absolute paths under `/home/<user>`. This program makes a scratch directory with `salsa`'s `files_mkdir`, writes with `files_touch`, reads back with `fileContent_get`, verifies the content, and then removes its own evidence with `folderByPath_delete`, which returns only once the CUBE confirms the folder no longer resolves (server-side deletion is asynchronous, so a fire-and-forget delete would race any rerun).
