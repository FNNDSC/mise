:toc: left

== What this is

The session API is the pairing of `@fnndsc/brasa` (the engine: parser, dispatch, builtins, pipes, session state, output sinks, surface capabilities) and `@fnndsc/calypso` (the daemon that hosts an engine behind a WebSocket, plus the zod-validated wire contract a client speaks). A program on this API exchanges command lines for command envelopes: structured results carrying rendered text, error text and status, exactly what the chell shell itself runs on.

== Why this is

Some programs are not scripts but surfaces: a web terminal, a chat integration, an agent that operates ChRIS conversationally. Such a program needs a session (working directory, connection, caches, history), needs interactivity to happen on the correct machine (a password prompt or a pipe through `grep` must run where the human is, never on a daemon host), and needs results as data rather than scraped text. The engine plus the wire contract provide precisely that, and the capability inversion is the load-bearing design: prompts, pipeline segments, shell escapes and local edits are surface capabilities the engine requests, so an attached client executes them locally and returns the outcome.

== How this relates to existing session machinery

chell's interactive REPL, `chell -c` one-shots, the `chell --daemon` host and `chell --remote` client are all thin arrangements of these same parts; nothing documented here is a side door. The forthcoming web surface is planned as another such arrangement. For the protocol itself, every message crossing the socket validates against the schemas in the link:api/modules/_fnndsc_calypso.html[calypso reference].
