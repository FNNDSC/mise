= ChELL Execution Modes: Interactive, Command, and Script
:toc:
:toc-placement: preamble
:sectnums:

== Overview

This document is about how `chell` is *invoked*: as a REPL, with one or more lines from the command line, or on a script file. What a script *is* — its lines, its `@` header, its variables, its assertions and how it stops — is the manifest language, specified once in `docs/manifest.adoc`. A script and a manifest are one format with one runner (`play`).

[cols="1,2,2"]
|===
| Mode | Invocation | Ends when

| Interactive | `chell`, `chell user@url` | you leave (`exit`, Ctrl-D)
| Command | `chell -c "line; line"` | the lines have run (with `-e`, at the first failure)
| Script | `chell -f file`, `chell file`, `./file` (shebang) | the file has played, or its first refused line
|===

A session's working directory, its held listing (the `@` handles) and its variables carry from line to line in every mode.

== Interactive Mode

[source,bash]
----
chell                          # the saved session, or offline
chell user@https://cube.example.org/api/v1/
----

A line is run when you press Enter. `help` lists the commands; `help <command>` shows one; `help variables` shows how a line names what a command answered.

== Command Mode (`-c`)

[source,bash]
----
chell -c "ls /home/alice"
chell -c "cd ~/uploads; ls -l; cat notes.txt"
chell -c 'A=$(ls ~/uploads); set A'
----

Lines separated by `;` run in order, in one session, so `cd` and variables carry from one to the next. A `;` inside quotes is text. By default every line runs; `-e` stops at the first line that fails and exits non-zero:

[source,bash]
----
chell -e -c "cd /nowhere; ls"    # stops after the cd
----

One invocation holds one connection, so several lines in one `-c` are faster than several invocations.

== Script Mode

[source,bash]
----
chell -f workflow.chell          # explicit
chell workflow.chell             # a path that names a file is a script
./workflow.chell                 # with #!/usr/bin/env chell on line 1
chell -f workflow.chell user@https://cube.example.org/api/v1/
----

A script file is played as a manifest (`docs/manifest.adoc`): `play <file>`, run by the engine on its own host. Each line is shown as it runs (`▸ …`). The first refused line stops the script, names the line, and the process exits non-zero, so a clean exit is the assertion that every line held. `-e` is accepted and changes nothing for a script.

Everything a manifest may hold, a script may hold:

[source,bash]
----
#!/usr/bin/env chell
# Convert one series to NIfTI and prove it.
@param        SERIES
@param        CONVERT = pl-dcm2niix-v1.0.2

cd ${SERIES}
C=$(${CONVERT})
expect run ${C.instanceId} status eq finishedSuccessfully
expect path ${C.outputPath} count --matching "*.nii*" --deep gt 0
----

A script with a required `@param` is refused before its first line unless the value is given, so it is run with `play` and `--param`:

[source,bash]
----
chell -c "play $PWD/convert.chell --param SERIES=/home/alice/uploads/brain"
----

The path is the host's: `chell -f` makes it absolute, so a CFS file of the same name is never taken by mistake. `play` given a relative path asks the ChRIS filesystem first and the engine's disk second.

== Auto-Detection

`chell <word>` treats the word as a script when it names a file on this host; otherwise as a connection target (`user@url`). `-f` always means a script.

== Flags

[cols="1,3"]
|===
| Flag | Effect

| `-c "<lines>"` | Run the lines and exit.
| `-f <file>` | Play the file as a script and exit.
| `-e` | With `-c`: stop at the first failing line. Scripts always stop at their first refused line.
| `-u <user>`, `-p <password>` | Log in as this user (with a URL).
| `--physicalFS` | Use physical CFS paths, skipping the logical-to-physical mapping.
| `--remote`, `--attach <url>`, `--door <url>` | Run as a surface attached to a calypso session instead of a local engine (`docs/calypso.adoc`).
|===

`chell --help` lists the rest.

== Troubleshooting

*Script not found.* `chell myscript.chell` treats a word that names no file as a connection target. Give a path: `chell ./myscript.chell` or `chell -f myscript.chell`.

*Shebang refused.* `chmod +x script.chell`, and check `chell` is on the `PATH` the shebang searches (`which chell`).

*A script stopped early.* That is the design: the line it names was refused. Fix that line, or, if the failure is expected, assert it instead with `expect`.

*A `;` split a value.* Quote the value: `chell -c "cd 'a;b'; ls"`.
